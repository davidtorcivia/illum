# 00 — References: what the four repos already know

Research input for **illum**. Four local clones under `refs/`; every claim below was read from code, with
`file:line` pointers (paths relative to each repo root). Format per technique: **Principle → Why it works → How

## 1. pie-site (the user's own site) — the parent

### 1.1 Architecture: what runs where

The central finding: **the site migrated from drawing at runtime to prebaked art, and the dead code is the fossil
record of that migration.** `js/illum.js:9` still states the creed ("drawn in one ink and its washes, plus one
accent; nothing is an image"), but today almost everything a visitor sees *is* an image, generated by the repo's
own code at build time.

| Layer | Where it runs | Tech | Status |

| `js/hatch.js` `field`/`draw`/`paintFrame` | browser | Canvas2D | dead; `speckle`, `hatchRect`, `noise2`, `rng`, `fit` still used (`main.js:98,326,362`) |

Payload (desktop + `-m` phone variants): `art/` 23 MB (initials 4.0 MB, horse 2.3 MB, voices 1.9 MB, brush 1.2 MB,
21 growth WebMs 53–794 KB each, garden stills 51–536 KB), `gardens/` 2.3 MB (leaf WebP + MP4 pairs, 87–184 KB),
`map/` 9.1 MB (`relief-l.webp` 4.0 MB alone, `wash.webp` 1.8 MB, `arrows.webp` 257 KB). JS that draws at runtime is
under 10 KB. The build is five Puppeteer scripts pointed at a running dev server (`localhost:4747`), a Lua CLI,
two Python/numpy scripts and ffmpeg; Chrome path hard-coded to macOS (`build_static.mjs:6`).

Why it moved: phones. `map.js:37-39` documents four plate-sized canvases at 0.75 scale costing ~250 MB; `main.js:563`
serializes alpha-video decoding on phones because each is a software decoder; `main.css:389-390` pins gardens to
their own compositing layer to stop scroll wobble. Runtime brushwork lost to memory and main-thread budget, so the
painting moved into the build and the browser became a compositor.

### 1.2 Techniques

**T1. Structure-tensor orientation field (two inputs, one primitive).**
- *Principle*: strokes should run along the local axis of a form (a leg's length, a stem, across a petal), not in
  one global direction.
- *Why*: a painter's or engraver's strokes describe form; a uniform hatch reads as a texture laid *on* the shape.
  The structure tensor gives a smooth, sign-free axis even where gradients cancel.
- *How*: `js/painter.js:13-44`. Mask → two-pass 8-neighbour **chamfer distance** (`:19-23`) → separable box blur
  (`:25-28`) → gradient outer products Jxx, Jxy, Jyy (`:30-34`) → three passes of an O(1) running-sum box blur at
  radius 7.5% of height (`:35-39`, three boxes ≈ Gaussian) → orientation `θ = ½·atan2(2Jxy, Jxx−Jyy) + π/2` and
  **coherence** `C = √((Jxx−Jyy)²+4Jxy²)/(Jxx+Jyy)` (`:40-42`). Where C is low the angle is blended toward 0 (the
  body's run, `:55-56`); a little simplex noise is added (`:58`). Because θ is a line field (mod π), the tracer flips
  by π when the new direction opposes the last step (`:89`). `tools/paintpass.js:144-150` builds the same tensor on
  **luminance** of an existing raster instead of a distance field.
- *Implication*: one `orientationField(scalarField, {blur})` → `{angle, coherence}` primitive with two front-ends:
  `fromMask` (distance field) for silhouettes, `fromImage` (luminance) for repainting any drawing. Box-blur-cubed
  is cheap enough for a worker at 1–2 Mpx; GPU port is trivial.

**T2. Position-hashed paint pass (temporal stability).**
- *Principle*: every random decision about a stroke is a pure function of *where* it is, never of draw order.
- *Why*: when frames of a growth animation are each repainted, a running RNG shifts all later strokes the moment
  one earlier stroke appears, so brushwork shimmers. Hashing (gridX, gridY, channel) makes a stroke identical in
  every frame where its pixel exists.
- *How*: `tools/paintpass.js:151` integer hash (`a·374761393 + b·668265263 + k·2147483647`, xorshift-multiply
  finalizer). Grid at spacing `sp`, jittered by `hash(gx,gy,pass)` (`:155-156`); skip transparent (`:157`); stroke
  takes the **colour of the pixel beneath** with alpha `0.55–0.95 × A` (`:159`), runs along T1's angle with a slight
  quadratic bow (`:161`); two passes (3.2/1.8 px spacing × scale, `:154`); the crisp original stays beneath at 60%
  (`:153`). Then a **thin-feature guard**: 2-px min-filter erosion of alpha; wherever the original survives in A but
  not in the eroded A (hairlines, tendrils, stars) the crisp pixels are restored (`:164-168`). The older inline copy
  in `build_section_gardens.mjs:80-110` uses a running LCG (`:92`) — the shimmering version this file replaced
  (and `build_section_gardens.mjs` itself looks superseded by `build_growth.mjs`).
- *Implication*: the library's RNG contract must be `hash(seed, ...coords)` first, streams second. Any filter that
  is applied per frame must be coordinate-hashed. The erosion guard is a reusable rule: "paint the masses, keep the
  hairlines".

**T3. Bristle brush stroke (one stroke, many hairs).**
- *Principle*: a thick stroke is hundreds of hairs sharing one envelope, each with its own start, end, tint and
  opacity; the ends tell the story (loaded touch-down, dry lift-off).
- *Why*: a filled shape has one edge; a bundle of hairs gives a ragged start, streaky body, and broken tail — the
  three cues the eye uses to read "brush".
- *How*: `js/brush.js:5-33`. Per-stroke genome (`:14`): swell position, slant, tail start, load, thinness, roughness.
  Half-width envelope `half(x)` = base + Gaussian swell + sinus wobble, ramped in at the start and tapered by `1−0.3x³`
  (`:15`); midline `mid(x)` slanted and gently waving (`:16`). 420 hairs (`:18`), each at lateral position `v∈[-1,1]`,
  outer hairs start later and end earlier (`:19`, `|v|²` shortening), tint ±13 around the base colour, alpha
  0.55–1, width 1.2–4.4 (`:20`). **Dry brush** (`:25`): past `tail`, a segment is skipped with probability
  `(u−tail)·1.8`. Touch-down blot: ellipse at the start (`:30-31`). Cached by key (`:4-6`).
- *Implication*: `bristleStroke(path, envelope, genome)` generalised to a *curved* centreline (it is straight here;
  `map.js:144-163` does the curved version by offsetting hairs along a route's normal). Output should be Path2D/
  canvas for runtime and baked atlas for perf.

**T4. Hairs along a curve + tooth breakup.**
- *How*: `js/map.js:136` `hair(pts, w)`: per segment width `w·sin(π·min(1, 1.1q))` (taper both ends), skipped where a
  procedural tooth `sin(x·.9+sin(y·.37)·3)+sin(y·1.13+sin(x·.23)·2)` exceeds 0.72 (`:135`). Strokes are generated in
  route space `(t, offset)` and mapped through the route's frame (`:144-157`); separate populations for wash band,
  body, touch-down bristles (`:153-157`) and head strokes converging to the point (`:159-163`). `painter.js:74`
  does the same skip against simplex noise ("the hair skips on the tooth").
- *Why*: dry-brush breaks are *spatially* coherent (paper tooth is a fixed field), so breaks line up across
  neighbouring hairs the way real dry brush does; random per-segment skipping would look like dashes.
- *Implication*: `tooth(x,y)` should be one shared paper field that every stroke consults — the same field that is
  drawn as the paper grain, so ink and paper agree.

**T5. Curve conditioning: centripetal Catmull–Rom → Chaikin ×2 → arc-length table.**
- *How*: `js/map.js:47-71`. Centripetal parametrisation (`|Δ|^0.5`, `:51-52`, no cusps/overshoot on uneven
  waypoints), 16 samples/segment, two Chaikin corner-cuts (`:61`), cumulative length table (`:62`), `f(t)` returns
  point + heading from a ±2–3-sample chord (`:68-69`, smooth heading), with linear extrapolation for `t<0` so a
  stroke can begin "before" its path (`:65`).
- *Implication*: the library's `Path` type should be arc-length parametrised with a frame `(x,y,θ)` at any `t`; every
  ribbon, hair, band and reveal depends on it.

**T6. Tapered ribbon outline with head.**
- *How*: `js/map.js:75-89`. One closed outline: width profile `wOf(t)` = round cap for `t<0`
  (`√(1−(t/CAP)²)`), loaded swell `1+0.1e^{−40t}`, power taper `W0→W1` by `t^0.8` (`:80`); left/right offsets along
  the normal (`:83`), arrowhead appended (`:85-88`). Emitted as an SVG path string.
- *Implication*: `ribbon(path, widthFn)` → polygon is the vector twin of T3; florilegium's taper/blade (§3) is the
  same idea with better profiles.

**T7. Prebaked raster revealed through a growing vector clip.**
- *Principle*: paint expensively once, reveal cheaply forever.
- *How*: `js/map.js:129-171` paints all ten arrows into one canvas at build time (`?buildarrows`, saved by
  `build_static.mjs:12-13`) or loads `map/arrows.webp`. Per scroll frame, `paintArrows` (`:193-199`) builds a Path2D
  of each arrow outline up to its progress `k` (T6) and `drawImage`s the painted canvas through that clip. Same idea
  in CSS for gardens: `main.css:333-336` animates `mask-size` of a gradient from the roots up; and the growth WebM
  (`main.js:550-582`) is the frame-accurate version.
- *Why*: per-frame cost is one path + one blit, yet the reveal shows full brushwork with no shimmer (the paint never
  changes, only how much is shown).
- *Implication*: a first-class `reveal(baked, clipFn(t))` primitive. It is the bridge between "museum-grade
  procedural" and "60 fps on a phone".

**T8. Soft regional wash: blur fill + stroke field feathered through a blurred mask.**
- *How*: `js/map.js:173-191`. Blurred polygon fill at 30% alpha (`:179`); 3400 short angled strokes in three
  ochres over the bounding area (`:184-186`); then `destination-in` with the *blurred* region (`:187-188`) so the
  marks fade out with no hard edge.
- *Implication*: `washRegion(poly, {marks, feather})`; the `destination-in`-with-blur trick is the cheap 2D-canvas way
  to get a feathered edge.

**T9. Engraved relief: hachures seeded on log-elevation contours.**
- *How*: `tools/build_map.py:105-157`. Smooth DEM (`σ=4.6`, "an engraver draws landforms", `:106`); slope and
  NW-light shade (`:107-114`). Seeds on contours of `log(E+250)` every 0.13 (`:121-128`) — log spacing keeps rows
  3–5 px apart on steep and gentle ground alike. Random order + 2.3-px occupancy grid for Poisson-like spacing
  (`:129-136`). Each hachure walks downhill until it drops one contour (`:139-145`), width
  `0.35+1.55·slope·(0.35+0.9·shade)` (`:148`), tapering `1−0.8(t/n)^0.8` (`:152`), with a round head (`:154-155`).
  Sea: horizontal ruling broken where "the burin lifts" (`:162-171`), concentric waterlines at distance 4/9/16/26 px
  (`:172-176`), coast heavier on the shadow side (`:178-184`). Output is **a luminance mask**, not an image: the page
  colours it via CSS `mask-mode: luminance` (`css/main.css:72`).
- *Implication*: "ink as alpha, colour at composite time" lets one bake serve every palette. The hachure algorithm
  (seed on iso-lines of a transformed field, walk the gradient, occupancy grid) generalises to any scalar field —
  shading a letterform's relief, a vignette, a cartouche.

**T10. Watercolour wash with pigment pooled at the edge.**
- *How*: `tools/build_wash.py:80-86`. `m` blurred by `soft`; `edge = clip(m − blur(m,4))·rim·3.5` (a high-pass, so
  pigment collects just inside the boundary, as a drying wash does); alpha modulated by low-frequency noise; applied
  **multiplicatively** `img·(1−a+a·colour)`. Belts with noise-warped boundaries (`:61-63,90-97`); brush-mark masks from
  a slowly turning angle field (`:65-73`) multiplied into washes (`:104-105`); blooms of paper colour (`:132-133`);
  cold-press tooth = band-passed noise multiplied in (`:135-136`).
- *Implication*: `wash(mask, colour, {strength, rim, soft})` is a ~10-line GPU shader (blur + high-pass + multiply);
  the most transferable "watercolour" rule in all four repos.

**T11. Obstacle-aware growth from DOM measurement.**
- *How*: `tools/build_growth.mjs:22-34` measures section and avoid-boxes with `getBoundingClientRect` in headless
  Chrome at 1440×900 (or 390×844 phone), converts to page-cm (`MM = 420/1440`, `gardens-config.mjs:24`), passes them
  to Lua as `PIE_OBSTACLES`. `tools/steppe-svg.lua:12-39`: Liang–Barsky segment/box test (`:15-23`) blocks branches
  whose line to their stem crosses text; `PIE_PUSH` deflects a main stem sideways round an obstacle with a smoothstep
  weight over 2 cm and kills it if the detour exceeds 2.5 cm (`:25-38`). `:134-155` cuts the page into a grid at
  every obstacle edge and keeps non-blocked cells as florilegium's free regions. Two or three seeds are layered so
  species interleave (`build_hero.mjs:1-4`); seeds that fail are retried at `seed+1000k` (`build_growth.mjs:37-40`).
- *Weakness inside the technique*: florilegium's source is monkey-patched by `gsub` on exact source text, guarded by
  `assert(n == 1, "…moved")` (`steppe-svg.lua:44-75`). Brittle by design.
- *Implication*: illum needs a native `avoid: Element[] | Rect[]` on every grower, measured at runtime, plus a
  "no growth across" rule (segment-vs-rect) and "deflect, don't clip" for main stems.

**T12. Symmetric evenly-spaced bands.**
- *How*: `js/kinds/steppe.js:73-84`. Count per side `k = round((side − 2c)/spacing)`, the same on opposite sides;
  pieces at `c + (len−2c)(j+½)/k`, centred on the side's midpoint; a dedicated corner piece. `even-pearls`
  (`:94-97`) forces an odd count so each side starts, centres and ends on a large pearl. The comment (`:67-69`) names
  the reason: initialis's own bands walk from one corner and "close with whatever gap is left".
- *Implication*: border layout must solve for symmetry (integer count per side, corner pieces) rather than step a
  fixed pitch round a loop. This is a taste rule encoded as an algorithm.

**T13. Geometry/ink separation (initialis "kinds" API).**
- *How*: `js/kinds/steppe.js:86-206`. A kind is `{family: 'band'|'pattern'|'corner', name, draw|geometry}`. Bands
  receive `{out, path, w, along(step) → [{x,y,a}], L, settings}`; patterns `{box, s, out, r}`; corners
  `{corners, s, out}`. They only push geometry into `out.polys / out.lines / out.dots`; initialis inks it with its own
  print pass. Units are 1000 across (`:10`), randomness only from the stream passed in.
- *Implication*: the right plugin boundary for illum — motif authors emit geometry; the library owns ink, paper,
  registration and ageing. Keeps every motif automatically on-palette and on-paper.

**T14. Smaller pieces worth keeping.**
- Stipple-by-point-in-polygon petroglyphs: jittered grid, even-odd test, 82% fill probability, dot radius jitter;
  lines as dotted runs (`js/illum.js:79-94`). The "pecked" look comes from the dropout, not the jitter.
- Staged grow-in closure: ops tagged with a time `t`, sorted, replayed to `k` (`illum.js:151-160`); `hatch.js:107-119`
  per-stroke delay `d` so strokes grow staggered. Cheap growth animation without a recorder.
- Twisted cord as repeated quadratic arcs at pitch 0.9·w (`illum.js:27-35`) and as filled lozenges in the kind
  (`steppe.js:133-149`).
- Muybridge horse as traced polygon (`steppe.js:52-62`) and as mask for the painter; `tools/muybridge_frames.py`
  extracts silhouettes from the 1878 plate for potrace. Public-domain source imagery as *masks*, never as pixels.
- Greedy label placement over 10 candidate offsets, rejecting plate-edge and label collisions, then hiding lettering
  under labels (`map.js:105-127`).
- Mis-registered print of a letter: paper-coloured keyline stroke, accent fill offset (+2.2%, +1.8%), ink fill on
  top (`illum.js:174-182`).
- Paper tooth as dataURL CSS variable: LCG noise + 4-px weave + simplex mottling, multiplied at 50% (`main.js:31-40`,
  `main.css:231`).

### 1.3 Taste rules in force

1. **One ink, its washes, one accent, on a paper** (`illum.js:9`). Six fixed triples (`illum.js:17-24`,
   `tools/palette.json`): earth-pigment inks (ochre `#8e2a17`, malachite, lapis, charcoal, bronze, madder), a
   complementary accent, bone papers `#ece6d8`–`#f1e9df`. Tones are `ramp(ink, paper)(t)` — a wash is ink diluted
   toward paper, never a new hue.
2. **Motifs from the subject's own world** (`illum.js:1`: "not from later manuscripts"): Corded Ware cord,
   pit-comb, sun wheel, steppe petroglyphs, Stipa/wormwood/tulip, Pontic flora with steppe pollinators only
   ("no hummingbirds", `steppe-svg.lua:4`). Provenance is the ornament's meaning.
3. **Determinism by position**, so animation never shimmers (T2) and every seed is reproducible.
4. **Grow round content, never under it; never clip a plant** (`steppe-svg.lua:41-42`, "a plant ends where it grows
   to"). No long repetitive horizontals (`:41`, footer stem removed).
5. **Even, symmetric borders; never a hairline, a zigzag, or a band crossing at corners** (`initials.js:11-12`).
6. **Thin things stay crisp; masses get painted** (T2 erosion guard).
7. **Every stroke unique** (`brush.js:35-42`: 64 prebaked strokes, round-robin, none repeated on a page).
8. **Perf is a taste rule**: the header arrives by CSS within ≤1.2 s even if art is late (`main.js:595-599`);
   phones get `-m` assets, one alpha decoder at a time, still images instead of video in Safari (`main.js:559`).
9. **Reduced motion respected** everywhere (`main.js:11`, garden `start()` falls back to stills, `:574`).

### 1.4 Weaknesses / limits

- **Everything is baked at one viewport** (1440×900 / 390×844). Gardens are measured on the live page then frozen;
  any copy edit or font change silently invalidates obstacle maps. `object-fit: contain` (`main.css:378`) hides
  mismatch rather than fixing it.
- **Toolchain sprawl**: Node+Puppeteer (macOS Chrome path), Lua, Python/numpy/scipy, ffmpeg, a dev server that must
  be running. Not reproducible in CI as written.
- **Payload**: ~34 MB of art/map/gardens. `relief-l.webp` alone is 4 MB for what is a 1-bit-ish line drawing — a
  vector or a tiled/LOD format would be an order of magnitude smaller.
- **Duplicated primitives**: LCG in `hatch.js:74`, `brush.js:8`, `map.js:133,178`; hash in `paintpass.js:151`; three
  different "tooth" functions (`map.js:135` sinusoid, `painter.js:74` simplex threshold, `brush.js:25` probability
  tail); structure tensor implemented twice; paint pass copied twice with different RNG semantics.
- **Non-determinism left in**: `painter.js:131` `grain()` uses `Math.random`.
- **Colour model**: sRGB hex lerp (`illum.js:13`, `brush.js:10` ±k per channel). Ink→paper ramps in sRGB go muddy
  and grey in the mid-tones; florilegium already uses OKLCH (§3).
- **Monkey-patching florilegium** by regex on source (T11).
- **Dead code** (~20 KB of illum.js/hatch.js/main.js) with no marker that it is dead.
- No accessibility semantics for art beyond `alt=""` and `aria-label` on SVGs — fine for ornament, but there is no
  notion of "decorative vs informative" in the API.
